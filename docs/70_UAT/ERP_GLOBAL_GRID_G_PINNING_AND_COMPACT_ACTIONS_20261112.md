# G · 全局 Global Grid 固定列 / 操作列宽 / 账号布局恢复修复

Owner 2026-11-12 在正式站 /logistics/china?view=4px 截图反馈：
「操作」被强制固定，列设置右侧固定 0 无法生效，历史订单的操作
列宽 350–390px 而许多行只显示「—」。相似情况存在于国内发货
其他视图、待分仓及同步总表。Owner 批准独立修复 G-P0 至 G-P3。

## 根因（基于真实仓库代码）
- 国内发货、待分仓、同步总表等业务列采用 AG Grid 的
  lockPinned/lockVisible/suppressMovable；OmsGrid.applyPins()
  强行把其计入 pin count，导致输入 0 被恢复为 1/2。
- GlobalGrid 的 requiredColumnIds 还禁止取消「操作」勾选。
- 累积速达订单 actions 设置 width=360、minWidth=350、
  maxWidth=390；已存账号偏好保留旧的过大宽度。
- 列设置整行使用可拖拽的 label，拖放会产生标签默认 click，
  把内部复选框切成隐藏，用户不知道为何一列消失。
- 恢复默认无条件触发 per_page=50 导航（即使已经 50），有机会
  在写入新偏好前重新加载旧布局，产生「恢复/反弹」现象。
- AG Grid 自带 pin 变化不会同步回 OmGrid 的输入计数，导致
  手动固定与账号记录不一致。

## 新规则
- 允许「右侧固定=0」；用户可以单独隐藏/显示「操作」列，
  调整其位置、宽度，并保留每个账号、每个 namespace 的布局。
- 国内发货速达累计视图默认右侧 0；常用操作页面和同步总表沿用
  现有默认值，但任何用户可改成 0（不强制锁死）。
- 4PX 历史「操作」默认 116px、最小 100px、最大 130px；
  同步总表「操作」默认 116px、最小 95px、最大 134px；
  同步进度原有宽度不改。已存在 360px 旧偏好被限到新约束内，
  不丢失其他列的宽度、顺序、可见性或用户固定列数量。
- 只有多操作项目出现紧凑「操作 ▾」菜单，唯一操作仍直接可点；
  无可用操作只显示「—」。海外/国内 Tracking、发货、复审、
  同步网站继续使用之前原生 API 与角色门禁。
- 保留 AG Grid 列设置的账号缓存与远端串行写入；不再触发无效
  50 条分页跳转。恢复默认将明确重建默认可见性。
- 拖拽列行改为 div，从语义和事件上与 checkbox 分离；
  列显示切换仅由实际勾选触发。
- 国内发货待审核/待发货等高频多按钮行，仍保留已经正式通过的
  直接操作控件宽度（不强行挤到 110px 导致截断），但不再锁定
  右侧且可以按需隐藏。供应商累计 4PX 采用紧凑菜单。
- 支持同步总表两个右侧列全取消固定。所有业务页只保留核心订单
  ID / SKU 等必要列，不再把操作列设为必选。
- 不改 routes、database、permissions、shipment/order domain、
  order exports、Tracking Apply、Woo 同步业务逻辑。

## 工程范围与门禁
- G-P0：共享 pin state 的用户零固定与列拖拽/可见性分离。
- G-P1：国内累计 Speeda 与 Sync 紧凑操作宽度/菜单。
- G-P2：旧偏好宽度上限、账号恢复、无效 reset 导航修复。
- G-P3：纯函数/组件/Vue/PHP/独立 Chrome 覆盖国内发货、
  待分仓、采购、库存、订单、同步表，特别检查
  右侧固定0、旧 360px 修复、拖放不隐藏、隐藏+刷新持久化、
  只读/没有操作时不生成空白操作按钮，以及原生业务门禁。
- 最终 GitHub PR 需要最新 main CI，再由 Owner 单独批准
  合并和受控 Production 发布。上线时必须使用最新真实
  Production 基线制作 allowlist 增量包，保留完整回退版本。
- Production Owner 验收清单：
  1. 速达订单 350px 空白消失，右侧固定可调到0；
  2. 「操作」可隐藏/恢复显示，可拖到任意列而不意外消失；
  3. 关闭侧栏/刷新后保持个人设置；
  4. 有权限的订单操作仍可通过「操作」菜单进入，业务安全门禁不变；
  5. 同步总表右侧两个列可解除固定，数据和筛选/同步状态正常；
  6. 待分仓及其他 Global Grid、原表回退、九视图工作区保持正常。
