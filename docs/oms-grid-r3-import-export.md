# BYL ERP OMS Grid — R3.4 Import / Export V1

Status: Draft PR #628, isolated UAT only; no Production change authorized.

## Approved UX contract
- Compact top-left toolbar: **导入 | 导出 XLSX | 导出 CSV**.
- 导入 opens a modal modeled after the OMS screenshot: **模板 1**, choose XLSX, download editable template, preview/errors and final confirmation.
- Template is downloaded from a real authenticated endpoint `/orders/oms/import/template` and includes two tabs: **批量订单导入** (required column headers in yellow, optional in gray), **使用说明**. First row headers are immutable for imports.
- One row = **one SKU item**. Rows with the same normalized external_order_number form exactly one manual **customer** order. The first row holds required order/date/address information; later SKU rows repeat the same external_order_number and fill sku/quantity/unit_price. Other order fields may be empty and inherit the first row; any repeated nonempty value must agree with the first row. V1 max **200 distinct orders, 2000 SKU rows, 100 rows/order**, XLSX <=5 MB. Larger batches should split into files.
- Import steps: **选择文件 → 上传并预检（零写入）→ 错误清单/待建订单展示 → 确认创建 → 订单号反馈**. Confirm requires the same XLSX file and a short-lived, user-bound proof of the previewed SHA-256.
- Source order ID `external_order_number` must be supplied and unique across archived and active records. ERP numbers are generated by existing OrderService::create, never imported or forced by spreadsheet.
- Each row has one SKU which must exactly and uniquely match an existing ERP product; amounts are per-unit prices (up to two decimals), quantity is a positive integer. Different SKUs never create additional ERP order identities when external_order_number is shared. The importer does not create missing products.
- Destination address required: recipient_name, country, province_state, city, address_line_1. Optional phone, postal code, line2, order_note and currency (default USD).
- The import **only creates customer/manual Orders**; it never marks shipped, allocates a warehouse, syncs WooCommerce or alters existing orders. Imported orders follow existing normal ERP order workflow.
- Import validation errors return JSON 422 with human-readable reasons, never a generic redirect.

## Permissions, audit and exactly-once claims
- All endpoints guarded by standard authentication and orders.view. Import additionally requires orders.create, and the existing KolOrderAccessScope prohibits customer imports for KOL-only specialists.
- Non-Production APP_ENV allowlist: local, staging, development, testing. In Production the endpoints return 404 even if the branch were merged.
- No new business logic or independent order writer: the importer delegates to OrderService::create (ERP identity, order-items, address, order.created audit).
- An all-or-nothing DB transaction creates the independent batch ledger and per-source unique claims; repeat confirm and parallel claims are rejected. A failed batch rolls back new order rows, associated audit, claims and batch record together.
- The new tables `oms_order_import_batches` and `oms_order_import_claims` do not change legacy Orders data or impose new uniqueness constraints on preexisting orders.
- The 15-minute preview token is signed/encrypted, user-bound and checked against the exact file hash on confirm; server rechecks products, duplicates and all validations immediately before writing.
- Known boundary: a simultaneous **legacy single-order** manual create is not protected by the import-only claim table (legacy orders do not have a source-ID uniqueness DB constraint). The existing conflict precheck still runs inside the import transaction; changing global Orders uniqueness requires separate production-data audit and approval.

## Export
- `/orders/oms/export`: authenticated, server-side, filters/order sort match R3 OMS Grid, with exactly **one row per SKU item**, repeated canonical ERP/source order identity per row, per-SKU quantity and order-level total quantity, plus useful fulfillment fields.
- XLSX max **2,000 orders AND 5,000 SKU rows**, because large PhpSpreadsheet workbooks can exhaust server memory. If more records match, UI disables XLSX and indicates to use CSV or refine the query.
- `/orders/oms/export?format=csv`: streaming CSV without XLSX count cap; UTF-8 BOM and CSV formula injection escaping. Does not download only visible AG Grid rows. Uses server-controlled access/scope; does not reveal new accounting cost/commission data.
- Existing original `/orders/export` stays unchanged for legacy pages and remains available.

## R3.5 one-SKU-per-row rule (2026-11-05)
- **Canonical grouping key:** `external_order_number`; case-insensitive and whitespace-trimmed. Each row MUST repeat this key. Order header data appears in the first occurrence only. Later lines blank-inherit it, but a nonempty conflicting date/address/currency/note causes row-specific preflight rejection. Interleaved rows are grouped correctly; keeping a contiguous block per order is recommended.
- A multi-SKU order is **still ONE ERP Order**; its items are separate `OrderItem` rows. Preview reports `count` as unique orders, `row_count` as individual SKU lines; one bad SKU row blocks **the entire file** (transactional).
- A max of 200 orders, 2000 SKU lines, 100 SKU lines per order; each item row has `sku`, `quantity`, `unit_price` mandatory. Removes the former fixed 5-SKU horizontal group cap.
- XLSX template `批量订单导入` has 15 columns, a `使用说明` tab and a **`示例-勿上传`** tab showing one order across two SKU rows and another independent order.
- OMS list adapter flattens one server-paginated order into N **visual SKU rows**. Server pagination and counts stay by canonical order. The ERP order number link repeats on every line to show grouping. Workflow status and actions appear only on the first SKU line, avoiding duplicate mutation buttons.
- In the grid, `SKU数量` is a per-line value; `订单总件数` is an optional column. A corresponding export line has both `SKU数量` and `订单总件数` and repeats ERP/source order identity; CSV and XLSX follow the same output semantics.
- No new customer/fulfillment/financial orders are created to represent line items. ERP's existing order audit, workflow and unique import claims remain authoritative.

**R3.5 note:** The OMS `SKU数量` column-filter matches a single item-line quantity on the server, not the order sum; `订单总件数` is separately available as a read-only optional total.
