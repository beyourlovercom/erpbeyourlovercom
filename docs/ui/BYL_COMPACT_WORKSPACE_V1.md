## 1. 目标与范围

**顶部极简、主工作区最大化、普通说明下沉、功能完整、统一复用。**

- 适用于 BYL ERP 所有新增、改造、升级、调整的页面；既有页面采用台账分批迁移，**规则生效不等于代码已改造或 Production 已发布**。
- ERP 国内发货 `/logistics/china` 全部业务视图为首个基准批次；其他 ERP 模块依 [改造台账](./PAGE_MIGRATION_TRACKER_V1.md) 逐步推进。
- 其他项目必须在其**本项目** `AGENTS.md` 中显式引用 `BYL_COMPACT_WORKSPACE_V1` 与本文件的 canonical locator，才能宣称纳入项目级强制治理；ERP 文档的合并不会自动修改其他仓库。
- 消费者商城、营销活动、博客等场景只继承「删无效留白、突出主内容」原则，不得机械移除必要的品牌介绍、转化引导、无障碍和法定披露。

## 2. 顶部必须压缩

- 尽可能紧凑地呈现面包屑、**唯一**页面主标题、必要导航/标签和核心操作；不允许重复占行的分类口号或大装饰性页头。
- 普通生产流程说明、冗余提示卡、长期成功提示、绿色常驻信息条和大面积空白不占据首屏。
- 业务视图 Tabs 应贴近主工作区；搜索/筛选/表格设置直接服务于表格，而非独立叠出多排空工具栏。
- **保留已批准的右上角 Page Header Action Zone**：页面级主要操作仍聚合于页头右侧；紧凑标准不是将所有按钮下移。
- 不因为紧凑而消失真实订单号、业务状态、权限、危险操作保护、页面主操作或用户必要导航。

### 设计目标（可随业务/可访问性合理调整）

| 部位 | 推荐目标 | 验收含义 |
| --- | --- | --- |
| 面包屑 | 11–12px | 低权重但可读 |
| 主标题 | 20–24px | 优先单行；不重复大标题 |
| 紧凑标题行 / 业务 Tabs | 约 36–44px/行 | 消除无效垂直间距 |
| 普通说明性顶部横幅 | 常态为 0px | 迁移至 Help Footer |
| 表格工具条 | 约 36–44px | 不丢搜索/列设置/操作 |
| 紧凑数据行 | 约 32–38px | 受用户密度偏好控制 |
| 页底帮助文字 | 约 12px，可读的灰色 | 不遮挡主内容 |
| 1440×900 桌面首行 | 尽量在内容区顶部约 220px 内 | 不是无条件硬编码，遵守业务及字体可读性 |

## 3. 主工作区最大化

- 表格、编辑器、主表单、审批与业务工作台才是视觉主体，应尽早开始并使用可用空间。
- 搜索、筛选、密度、列设置、最大化等工作区级工具相邻聚合；不可永久暴露无用大面板。
- 业务表格必须继续遵守 `BYL_GLOBAL_DATA_GRID_VI_V1_1`：身份列固定左边、行操作固定右边；列设置默认使用表头右侧 `…` 入口；账户级列偏好、权限清洗、分页/排序/查询权威不改变。
- 间距优先复用 4/8/12/16px 节奏、共用布局组件；同类型视图不得复制一套不同的 CSS 使高度漂移。
- 提升可见内容空间时，不允许以丢失原来已批准的信息、功能或可访问性为代价。

## 4. 普通说明移至页面底部 Help Footer

- 包含操作流程、常规注意事项、生产连续性规则、非关键帮助信息；主内容之后统一用 1–3 行小号灰字，超长内容可展开。
- Help Footer 必须使用真实可选中文字；不可覆盖表格、最后一行、固定操作区或分页。
- 正常成功反馈采用短暂 Toast 或操作就近反馈，不在顶部留常驻成功条。
- **强制例外：** 阻断性错误、保存失败、权限不足、必填项校验、危险操作确认、需要马上处理的警告，一律保留在操作上下文中明显呈现，绝不可藏至页脚。

国内物流页脚参考（上线前核对真实业务流程）：

> 帮助：① 正常订单继续发货；缺电话、单号/Tracking 冲突只隔离对应订单，不阻断整批。② Vita 分仓 → Kaven/运营确认有货 → Liang 发货 → 承运商文件回传 → Tracking Preview → Apply。③ 单个异常订单不阻断其他正常订单。

## 5. 各端适配

- **桌面（≥1280px）：** 标题/应用标签紧凑并列、业务 Tabs 紧贴、工具栏后立即进入表格。
- **窄桌面/平板（768–1279px）：** 减少页边距；多 Tabs 可横向滚动，核心操作仍在可访问的位置。
- **手机（<768px）：** 缩短头部，保证点击目标足够大；次级工具可以收起，绝不缩小到不可操作；关键状态和错误就近可见。
- 水平滚动数据表必须仍能识别身份列、状态与操作；兼顾键盘导航、字体可读性和对比度。

## 6. 与现有最高规则的兼容

本规范是**Owner 批准的视觉密度与内容优先级规则**，但不凌驾于业务正确性/安全/权限/无障碍规则。尤其必须同时遵守：

1. `AGENTS.md` 的 **HIGHEST OWNER VISUAL APPROVAL / UAT GATE**：先渲染，Owner 视觉 PASS 后开发；真实 Local/UAT 页面 Owner PASS 后才能正式收口。
2. **HIGHEST PAGE-LEVEL ACTION PLACEMENT GATE**：页面级操作留在右上角；表格行操作、字段内操作遵守各自上下文。
3. [表单设计标准](../10_Planning_Roadmap/18_BYL_ERP_FORM_DESIGN_STANDARD_V1.md)。
4. [Global Data Grid VI V1.1](../10_Planning_Roadmap/26_BYL_ERP_GLOBAL_DATA_GRID_VI_V1_1.md)。
5. ERP 原有订单变更/权限/数据真实性/发布治理；本次仅为视觉和布局标准，**不改变任何业务状态或授权**。

遇到明确冲突，应先记录冲突与适用条款，申请 Owner 裁决，不可静默放宽现有规则。

## 7. 默认工程实现

- 优先抽取或复用 `CompactPageHeader`、`ViewTabs`、`WorkspaceToolbar`、`HelpFooter`（为逻辑角色描述，实际命名以现有项目实现为准），先改共享层，后完成视图回归；避免每视图复制独立 CSS。
- 尽量最小化布局差异，不触动订单状态、分仓、物流、追踪号、权限、同步与资金逻辑。
- 刷新后须保持用户已保存表格布局、标签状态及未保存草稿策略；不能出现初始布局闪切。
- 不通过额外动画、长时遮罩、空 DOM 达到视觉紧凑；关注 CLS、首屏渲染和长时间工作稳定性。
- 防止 CSS 全局污染；不要把本规则当成强制重写所有页面的理由。

## 8. 逐页实施与验收门禁

| Gate | 要求 | 结果记录 |
| --- | --- | --- |
| G0 基线盘点 | 确认菜单/路由、真实页面、用户任务、无效顶部提示、需保留操作 | 台账填写基线状态 |
| G1 视觉确认 | 代表性桌面渲染，必要时手机方案；Owner 显式 PASS | `DESIGN_PASS` |
| G2 Dev 实施 | 共用组件优先，保持原数据和权限 | PR + exact head SHA |
| G3 自动/功能回归 | UI/类型/构建、按钮/搜索/列设置/权限/持久化与安全告警 | Evidence / CI |
| G4 真实 UAT | Agent 提前打开所有受影响 Local/UAT 页面；Owner 检查并 PASS | `OWNER_UAT_PASS` |
| G5 发布与生产复核 | 根据已有连续授权执行常规 PR 合并；Production 单独 Owner 授权，之后读回验证 | `MERGED` / `PROD_PASS` 分开 |

**未过 Owner 视觉 PASS 不得提前改视觉代码；未过 Owner 真实 UAT PASS 不能标记完成；Git 合并不等于已部署。**
