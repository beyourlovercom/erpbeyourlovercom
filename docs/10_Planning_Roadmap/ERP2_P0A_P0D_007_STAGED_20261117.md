## P0-A: persistent session contract — code QA PASS, live 60-day proof HOLD
- Local opaque HttpOnly SameSite=Strict cookie and server-side session limit: 60 days (5,184,000 seconds).
- Login includes `remember=1` to request Laravel's standard persistent login.
- Laravel cookie jar never leaves the bridge; local session is AES-256-GCM encrypted at rest.
- The 256-bit encryption key is protected by Windows current-user DPAPI under `LOCALAPPDATA\BYL\ERP2-Identity-Dev`; no key, upstream cookie or employee credentials in Git.
- Auth state survives the isolated Dev bridge process restart if launched under the same Windows account.
- IMPORTANT: current versioned Laravel `config/auth.php` defaults `AUTH_REMEMBER_DURATION` to 30 days (minutes). A 60-day Dev cookie cannot override the upstream Laravel remember-token lifetime. True 60-day end-to-end validity requires separately validating upstream effective config and obtaining explicit authority before any Production config change.
- A nonmatching Windows user or invalid encrypted session store fails closed. No synthetic identity fallback.

## P0-B: transient failure vs verified revocation — PASS
- HTTP 401/403 or explicit redirect to `/login` from the original identity authority => purge encrypted local session and return 401.
- Timeout, 5xx, unrelated redirect or malformed/temporarily missing response => return 503, keep the opaque cookie and encrypted state; do not treat this as successful authorization.
- Next successful request must verify the original Laravel identity and live permissions again before returning any effective rights.
- `/orders`, `/customers/orders` and `/api/*` remain forbidden (405); no order data is read.

## P0-C: stable authorized sidebar — PASS
- First successful identity verification creates authorized menus once; route navigation reuses the in-memory verified allowed-path set.
- Background revalidation at 60-second intervals while visible, plus window focus; no re-fetch or sidebar clearing on every navigation.
- Transient identity errors preserve currently displayed menus, tabs and hot snapshots (without granting server access).
- Real identity/role/permission changes rebuild the menu and invalidate stale pinned tabs, hot data and disallowed paths.
- Explicit logout during in-flight verification cannot resurrect a removed identity.
