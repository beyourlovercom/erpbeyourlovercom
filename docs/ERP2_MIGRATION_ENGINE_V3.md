## Run the closed-loop checks
From the verified ERP2 workspace (007windows by default), use the actual source and target roots. Node 24, Vue compiler-sfc and TypeScript must resolve from the supplied dependency base. Copy and adjust the example config to the correct absolute roots and source revision. Do not scan secrets or personal order data. Independently verify ERP1 production hashes/source revision and ERP2 actual deployed build before treating scans as runtime evidence.

1. `node ops/migration-engine-v3/engine.cjs scan CONFIG REPORT DEPENDENCY_BASE` recursively inventories Vue SFC imports, local TS dependencies, controls, inherited conditions, events, component bindings, column definitions and literal route expressions. Dynamic behavior, server decisions and framework-wide dependencies require further semantic evidence. Unresolved imports/parse errors block. The scan is deliberately conservative across all reachable views/shared modules; candidates are not a count of unique business features or confirmed defects.
2. `node ops/migration-engine-v3/init-manifest.cjs REPORT BUILD_DIR NEW_LEDGER` creates a source-driven per-item OPEN ledger with suggested targets, never overwriting evidence. Similar labels are candidates, not PASS. Resolve each applicable source item against actual target behavior, including alternative state branches and shared framework replacements. Record precise reasons and Owner-approved exclusions; do not suppress unmatched rows. Include backend route/controller/service, permissions, state/field/UX contract and actual source revision as semantic evidence.
3. Reuse original standalone components where feasible; adapt transport to canonical Laravel and preserve Unified Grid V2, session, feedback and safety. Do not automatically copy business mutations or relax permissions. Build and test an independent candidate with shared locks; re-scan exact candidate and generate a new ledger bound to its hashes. A renamed, copied, hidden or unbound control is not equivalent. Compare all actual conditional states, selected rows, popovers, fields, responsive layouts and negative cases.
4. `browser-inspector.ps1` provides read-only real dual-site UIAutomation on existing Chrome using its own two-tab window on 007windows. Run through an authorized script policy/approved DC command; never modify execution policy or credentials. It captures allowlisted UI labels/rectangles and exact URLs, not customer/order data. It never certifies actor identity or comparable records and never submits an operation. Add independent same-role, comparable-record real browser workflow proof, using only isolated Dev fixtures for mutations; production read only. Mock browser, CI and screenshot alone cannot satisfy S08. Do not replace actual visual assessment with label counts.
5. Fill the manifest with evidence: each VERIFIED source ID needs exact target IDs and a JSON evidence artifact with kind semantic-action-review, version 3, route/view, sourceTreeHash, targetTreeHash, buildHash, buildTreeHash, result PASS, meaningful provenance, sourceId and targetIds. NOT_APPLICABLE needs exact Owner scope-exception evidence with sourceId and reason. Each S01–S08 needs separate v2-gate-S0n evidence. Real browser evidence must additionally contain mode REAL_DUAL_SITE, verified actor, same role, comparable record and verified workflow, as documented in the manifest. Owner-final-uat evidence must be actual Owner approval. Each reference includes path and SHA-256. Structured metadata is not independent authentication; never manufacture evidence or mark a mocked fixture as real. Keep evidence access controlled, and have independent reviewer verify provenance.
6. `node ops/migration-engine-v3/preflight.cjs CONFIG LEDGER DEPENDENCY_BASE RECEIPT` rescans current source and target and checks entire candidate build tree, evidence content/hash, mappings, V2 gates and actual browser/Owner evidence. Exit 2 = BLOCKED; exit 0 = eligible for separate release authorization, NOT authorization itself. Run for every affected route/view before a parity-complete release; no omitted route. For an approved Node cutover script, `node ops/migration-engine-v3/guarded-release.cjs CONFIG LEDGER DEPENDENCY_BASE RECEIPT -- SCRIPT [ARGS]` starts no script on a failed preflight and checks exact authorized script path/hash/args/reference before invoking. Preserve existing production authorization and safety gates. Integrate this check into the actual cutover path; manual execution outside it is not mechanically protected. CI below tests the tool, not page acceptance. All-page deployment-pipeline enforcement follows the first fully accepted pilot, not assumed by this PR.
