# 速达 / 4PX 2026-10-26 官方新版导出契约（R1–R4）

## 来源与范围
- 来源：Owner 上传 `速达--新模版1026（26款）(1).xls`（标准上传格式、国家对照表）。**原文件含真实收件人信息，不进入 GitHub。**
- XLS BIFF 只读检查确认上传格式 **A:AA 共 27 列**；原 A:X 24 列名称和排列未变化。
- Y（第 25 列）：商家产品识别码 → ERP 已核实的履约 SKU。
- Z（第 26 列）：制造商产品识别码 → Product OS `products.barcode_69`（文本，保留前导零）。
- AA（第 27 列）：国际标准商品编码 → **始终留空**，不允许自动填充 GTIN。
- 国家对照表继续保留；ERP 导出文件仍为 .xlsx，列结构符合新模板。

## 业务规则
- **仅速达 4PX** 改为 27 列；纬狮 Weship 仍单独使用原 24 列模板，旧导出/回传接口不变。
- 欧洲目的地（支持 EU/英国/挪威/瑞士等现有欧洲小包国家清单）：Y/Z 从订单行精确关联 Product OS 取得；不得模糊识别 SKU，不得以其他条码代填。
- 非欧洲目的地：Y、Z、AA 留空，不强制产品条码。
- 1 个 SKU 多件或多条同 SKU 行：Y/Z 使用唯一 SKU 与 69 码；原 Q 列继续填数量合计。
- 多个不同 SKU 的欧洲订单：由于官方 Y/Z 仅各有一个字段，**逐单阻断并展示原因**，不得拼接多个条码、覆盖其中一个、复制成多个包裹或重复下单。
- 欧洲缺条码、产品身份不一致、SKU 无唯一精确匹配：逐单阻断；其他可安全导出的订单继续导出。
- 原 A:X、国家对照、重量/品名/数量、IOSS、回传模板及审核流程保持不变。

## 代码实现
- `SpeedaOutboundExporter` 在原稳定基础模板上构造 Y:AA 3 列并复制行样式，避免改动稳定的旧字段。
- `ChinaSmallPacketBarcode69Reader` 负责已有 SKU / 69 码核实；`SpeedaOutboundExporter::blockers` 负责逐单 Preview/阻断。
- `DomesticLogisticsController` 传入正确承运商标签，防止纬狮订单错误触发速达条码要求。
- UI 明确显示 4PX 27 列模板、Weship 24 列模板。

## UAT 目标
1. 官方 27 列名称/顺序精确；欧洲订单 Y=SKU、Z=条码文本、AA=空。
2. 13 位条码前导零保留；多行导出每行正确复用 Y:AA 样式。
3. 非欧洲订单不强制条码；无条码/多 SKU 欧洲订单仅阻断对应订单。
4. 原 A:X、纬狮 24 列、国内物流和回传流程回归。
5. 仅限隔离测试；未经 Owner 后续 PASS 不合并也不更新正式 ERP。
