- 停止 ERP2 独立升级及同步发布；ERP V4 原生反向 UI 迁移不受影响。正式启用状态以发布回执为准。

## 2026-11-26

### 设置 / 数据库备份（ERP1、ERP2）

- 备份与下载分为两个独立操作：点击「立即备份数据库」，成功后即可继续工作；可随时下载已保存的备份，重复下载不重新导出数据库。
- 完整备份 MySQL 表结构和数据，保存至各自服务器私有 `/backup/` 目录，最多保留最近 3 份；仅授权管理员可操作，不启用自动定时备份。
- 修复大文件压缩超过 PHP 30 秒限制的问题，采用快速 GZIP 压缩和备份专用执行时限，保留完整性校验；修复 ERP2 网关下载编码及超时问题。
- ERP1 于北京时间 16:39 发布，16:40 的真实备份通过 GZIP 完整性检查；ERP2 于 16:41 同步发布，独立测试环境已验证重复下载不产生新备份。
- 相关变更：PR #873、#874、#877、#881。

### 网红 / 历史账号（ERP1）

- 支持创建缺失的 ERP 网红档案并绑定已有 WordPress / AffiliateWP 账号和原优惠码（如有），不重复开通账号或重置密码。
- PR #871 已在 ERP1 发布；ERP2 网红建档页面仍待完整发布验收，不计为已上线功能。

### 发布规范（ERP1、ERP2）

- 常规页面及业务修复默认不要求数据库备份；涉及数据库结构、数据迁移、批量修改或删除等高风险发布，须先完成数据库备份。
- 保留代码回滚点、CI 检查和发布后验证；备份成功即可作为发布保护，无需下载数据库。
